Language / Tests

Tests

test name() { ... } and loom test.

A test is written like a function, with test in place of fn. It takes no parameters and returns nothing, or ! E so it can use ?. loom test FILE runs the file's tests one after another and prints a report like cargo's.

samples/tests_pass.loomtests pass
use std.io.print

fn clamp(n: i32, lo: i32, hi: i32) -> i32 = if n < lo { lo } else if n > hi { hi } else { n }

// A test is written like a function, with `test` in place of `fn`.
test clamps_low() = assert(clamp(-5, 0, 10) == 0)

test clamps_high() {
    assert(clamp(50, 0, 10) == 10, "50 should clamp to 10")
}

// A test may return an error, so it can use `?`.
test parses_ports() ! any Error {
    assert("8080".parse[u16]()? == 8080)
}

// A passing test prints nothing.
test quiet() {
    print("you only see this when the test fails")
}

// Tests aren't part of the program: `loom run` leaves them out, and
// there's no `main` here.
Test report
running 4 tests
test clamps_low ... ok
test clamps_high ... ok
test parses_ports ... ok
test quiet ... ok

test result: ok. 4 passed; 0 failed
  • A test passes when it returns. It fails when it unravels (a failed assert, say) or returns an error.
  • A passing test prints nothing. For a failing one the report shows what it printed, and then why it failed.
  • loom test runs every test, even after one fails. A file of tests needs no main.
  • Tests exist only for loom test. loom run and loom build leave them out, and nothing can call one: a test's name isn't in scope, so a test and a function can share it. Two tests can't.
  • Tests go at the top level of a module (S0212 inside a function). A test with the wrong signature is T0119.
  • Every command type-checks tests, so loom check catches a broken one.
samples/tests_fail.loomtests fail
use std.io.print

warp Oops: Error {
    case Bad(n: i32)
}

fn half(n: i32) -> i32 ! Oops {
    if n % 2 != 0 { fail .Bad(n) }
    n / 2
}

test halves() ! Oops {
    assert(half(8)? == 4)
}

// A test fails when it returns an error...
test odd_number() ! Oops {
    print("about to halve 3")
    let h = half(3)?
    print("never printed: {h}")
}

// ...or unravels. `loom test` runs every test, even after a failure.
test wrong_length() {
    let xs = [1, 2, 3]
    assert(xs.len() == 4, "three is not four")
}

loom test exits with 0 when every test passed, 1 when one failed, and 70 when a test hit a bug in Loom. Tests run unsandboxed: they can read the environment and files.
