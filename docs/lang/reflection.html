Language / Reflection

Reflection

What compile-time code learns about a type, and default methods that derive from a type's shape.

Compile-time code can ask a type about itself. The answers are known while compiling, like a const parameter, so const if and const for can use them, and nothing reflective is left in the program. The types involved are in std.meta.

Asking a type

ExpressionGives you
T.nameits name, "Point" (a warp's, without its arguments)
T.kinda case of Kind: .Record, .Sum, .Int, .Str, .List, …
T.fieldsa record's fields, a list of Fields
T.casesa sum's cases, a list of Cases
T.size, T.alignhow many bytes a value takes, and what its address is a multiple of
f.name, f.is_pub, f.offseta field's name, whether it's pub, and where it starts in the value, in bytes
c.name, c.fieldsa case's name, and its payload's fields
.len(), .is_empty()of T.fields, T.cases or c.fields

Two things use them in code that runs:

  • v.(f) is v's field f, where f is a Field. It reads and assigns like v.x.
  • v is .(c) tests whether v is case c, and v.(c).(f) reads a field of that case's payload. Read it inside if v is .(c): on any other case it unravels.

const for f in T.fields writes its body out once per field, so describe below turns into straight-line code for each type it's called with.

samples/refl_describe.loomruns
use std.io.print

warp Point: Show {
    pub x: i32
    y: i32
}

warp Shape: Show {
    case Dot
    case Circle(r: f64)
}

fn describe[T](v: T) {
    print("{T.name} is a {T.kind}")
    const if T.kind == .Record {
        const for f in T.fields {
            print("  {f.name} = {v.(f)}")
        }
    } else if T.kind == .Sum {
        const for c in T.cases {
            if v is .(c) {
                print("  case {c.name}")
                const for f in c.fields {
                    print("    {f.name} = {v.(c).(f)}")
                }
            }
        }
    }
}

fn main() {
    describe(Point(1, 2))
    describe(Shape.Circle(r: 1.5))
    describe(Shape.Dot)
}
Output
Point is a Record
  x = 1
  y = 2
Shape is a Sum
  case Circle
    r = 1.5
Shape is a Sum
  case Dot

Derive is a default method

Loom has no derive macros. A weft gives a default method that looks at Self, and every warp that lists the weft gets that method, worked out for its own fields. examples/compile_time.loom writes ToJson this way.

samples/refl_derive.loomruns
use std.io.print

/// Anything that can list its fields. The default body works for any
/// record: `const for` writes out one line per field.
weft Fields {
    fn fields(self) -> String {
        var out = String()
        const for (i, f) in Self.fields.indexed() {
            const if i > 0 { out.push_str(", ") }
            out.push_str("{f.name}={self.(f)}")
        }
        out
    }
}

warp Point: Fields { x: i32, y: i32 }
warp User: Fields { name: String, age: u8 }

fn main() {
    print(Point(3, 4).fields())
    print(User(name: "Ada", age: 36).fields())
}
Output
x=3, y=4
name=Ada, age=36

Writing the method yourself replaces the default, like any other default method.

Sizes

T.size, T.align and f.offset are how values are laid out in memory: fields ordered by alignment (the largest first), cases sharing space behind a tag, and ?T costing nothing when T has bit patterns it never uses. Both backends give the same answers.

samples/refl_layout.loomruns
use std.io.print

warp Header { flag: u8, len: u32, id: u16 }

warp Token {
    case Word(String)
    case Number(u64)
    case End
}

type MaybeToken = ?Token

fn main() {
    print("Header: {Header.size} bytes, aligned to {Header.align}")
    const for f in Header.fields {
        print("  {f.name} at {f.offset}")
    }
    print("Token: {Token.size} bytes, ?Token: {MaybeToken.size}")
    const assert(Header.size == 8, "the header changed size")
}
Output
Header: 8 bytes, aligned to 4
  flag at 6
  len at 0
  id at 4
Token: 32 bytes, ?Token: 32

Only while compiling

A Field, a Case or a list of them has no value when the program runs. Anything read from one does: a name is text, .len() is a number. Keeping the list itself is K0111.

samples/refl_err_runtime.loomdoesn't compile: K0111
use std.io.print

warp Point { x: i32, y: i32 }

fn main() {
    print(Point.fields.len())
    let fields = Point.fields
}

Not supported yet

  • T.bits (for #layout(bits)), f.ty and T.weaves(W) are U0102.
  • std's Show, Eq, Ord and Hash for warps are still built into the compiler rather than written as default methods with reflection.
