Language / Moves, once and defer

Moves, once and defer

Who owns a value, what a parameter can do with it, and what runs when a scope ends.

Values first

Every variable owns its value. There is no type "reference to T", so there are no lifetimes to write. Assigning a value or passing it to a take parameter copies it if its type is Copy and moves it otherwise. A warp whose fields are all Copy is Copy by itself, unless it's a once warp.

A function's parameters say what it may do:

DeclaredCall siteThe callee
x: Tf(x)reads x; the caller keeps it
mut x: Tf(mut x)edits x in place; the caller keeps it, changed
take x: Tf(x)owns x; the caller loses it unless T is Copy

mut is written at the call site as well as the declaration. Method receivers are the exception: scores.sort() is already clear.

samples/own_params.loomruns
use std.io.print

warp Counter: Show {
    n: i32 = 0
}

// `x: T` reads. `mut x: T` edits in place. `take x: T` consumes.
fn peek(c: Counter) -> i32 = c.n
fn bump(mut c: Counter) { c.n += 1 }
fn swap(mut a: i32, mut b: i32) {
    let t = a
    a = b
    b = t
}
fn keep(take names: List[String]) -> usize = names.len()

fn main() {
    var c = Counter()
    bump(mut c)                              // `mut` is written at the call, too
    bump(mut c)
    print("{peek(c)} {c}")

    var a = 1
    var b = 2
    swap(mut a, mut b)
    print("{a} {b}")

    // Mutable exclusivity works per field.
    var pair = (10, 20)
    swap(mut pair.0, mut pair.1)
    print(pair)

    // Assigning a `Copy` value copies it.
    var d = c
    d.n = 100
    print("{c.n} {d.n}")

    let names: List[String] = ["ada", "alan"]
    print(keep(names))
}
Output
2 Counter(n: 2)
2 1
(20, 10)
2 100
2

Moves are checked

Using a variable after it moved is an error, and so is moving a value out of a borrow (a read parameter, a loop's item, a lambda's captured variable) or out of a list's element. The check follows branches and goes through loop bodies twice.

fn keep(take s: String) -> String = s

fn used_after(take s: String) -> usize {

    s.len()

fn main() {}

A borrow lasts as long as the call that received it, so a function can't return one or store one. A local can hold a value that borrows another local (a slice of a list, a stream over one, a lambda), and it sees that local as it is now. When the local changes, a borrow made earlier can't be used:

use std.io.print

fn main() {
    var xs: List[i32] = [1, 2, 3]
    let tail = xs[1..]
    xs.push(4)
    print(tail)
}

6 |     xs.push(4)

Nor can a borrow outlive what it borrows. A lambda that uses variables around it is passed as an argument or kept in a local, and that's all: returning it, storing it in a warp or a list, or passing it to a take parameter is an error, and so is keeping it in a variable declared outside the block of a variable it uses. The same goes for a slice of a local list, and a stream made from one or from such a lambda. (A lambda that uses nothing around it is a plain function value, and goes anywhere.)

once warps

A once warp describes values that must be used up exactly once. They can't be copied, and they can't just go out of scope. The ways to use one up are to destructure it (let Tx(moves) = self, which only code that can see its fields may do) or to pass it to a take parameter that does. A warp that holds a once value is once itself, and so is List[Tx].

samples/own_once.loomruns
use std.io.print

// A `once` value must be used up exactly once. Here that means calling
// `commit` or `rollback`, which take it and unpack it.
pub once warp Tx {
    moves: List[i32] = List()

    pub fn begin() -> Tx = Tx()
    pub fn credit(mut self, amount: i32) { .moves.push(amount) }
    pub fn commit(take self) {
        let Tx(moves) = self                 // destructuring ties the value off
        print("committed {moves}")
    }
    pub fn rollback(take self) {
        let Tx(_) = self
        print("rolled back")
    }
}

fn transfer(good: bool) {
    var tx = Tx.begin()
    defer tx => tx.rollback()                // runs only if `tx` is still loose
    tx.credit(5)
    if not good { return }                   // leaving early rolls back
    tx.commit()                              // used up: the defer does nothing
}

fn main() {
    transfer(true)
    transfer(false)
}
Output
committed [5]
rolled back

The compiler tracks each path. A once value that might still be loose when its scope ends, or when a return, fail, ? or break leaves, is a loose end:

defer

defer runs code when its scope ends, however it ends: normally, or through return, fail, ?, break, continue or an unravel. Defers run in reverse order of declaration. A return value is worked out before the defers run. A defer can't change control flow: return, fail, ?, break and continue in one are T0118.

samples/own_defer.loomruns
use std.io.print

fn plain() {
    defer print("declared first, runs last")
    defer print("declared second, runs first")
    print("body")
}

// The result is worked out before the defers run.
fn returns(n: i32) -> i32 {
    var x = n
    defer print("defer sees x = {x}")
    if n > 5 { return x * 10 }
    x += 1
    x
}

warp Oops: Error {
    case Bad
}

// A defer runs on every way out: `return`, `fail`, `?`, `break`,
// `continue`, and an unravel.
fn fails(bad: bool) -> i32 ! Oops {
    defer print("cleanup after fails({bad})")
    if bad { fail .Bad }
    1
}

fn main() {
    plain()
    print(returns(3))
    print(returns(9))
    print("{fails(false):?}")
    print("{fails(true):?}")

    for i in 0..4 {
        defer print("end of iteration {i}")
        if i == 1 { continue }
        if i == 2 { break }
        print("iteration {i}")
    }
}
Output

declared second, runs first
declared first, runs last
defer sees x = 4
4
defer sees x = 9
90
cleanup after fails(false)
ok(1)
cleanup after fails(true)
err(Bad)
iteration 0

end of iteration 1

A fallback defer, defer tx => tx.rollback(), names a once value and runs only on exits where that value is still live. It's how the transfer function above rolls back on an early exit without doing it after a commit. Giving tx a new value re-arms it.

Pointers

^e puts a value in a box on the heap and gives a pointer to it, written ^T. A pointer owns its box: it moves like any non-Copy value, and dropping it drops the value and frees the box. That is how a type holds itself (^Tree inside Tree). p^ reads the box. Fields, methods, patterns and {p} see through a pointer, so t.value and match t { .Node(l, x, r) => ... } work on a ^Tree. A pointer in a var can be written through (p.x = 1, p^ += 1).

samples/own_pointers.loomruns
use std.io.print

warp Tree {
    case Leaf
    case Node(left: ^Tree, value: i32, right: ^Tree)
}

fn insert(take t: ^Tree, v: i32) -> ^Tree = match t {
    .Leaf => ^Tree.Node(^Tree.Leaf, v, ^Tree.Leaf)
    .Node(l, x, r) => if v < x {
        ^Tree.Node(l.insert(v), x, r)
    } else {
        ^Tree.Node(l, x, r.insert(v))
    }
}

fn sum(t: ^Tree) -> i32 = match t {
    .Leaf => 0
    .Node(l, x, r) => l.sum() + x + r.sum()
}

fn main() {
    var t: ^Tree = ^Tree.Leaf
    for v in [5, 2, 8, 1, 9, 3] {
        t = t.insert(v)
    }
    print("sum {t.sum()}")

    var n = ^41
    n^ += 1
    print("{n^}")
}
Output
sum 28
42

A take pointer that a match takes apart hands its parts to the arms by value, so the arms can move them into a new node.

Spools

A pointer into the heap owns its box and frees it. When many values live and die together (the nodes of a tree, a frame of a game) a spool is cheaper: spool frame = Arena(1.kib()) makes one, frame.put(v) moves a value into it, and ^e allocates in the spool a function is given. A pointer into a spool is Copy and owns nothing; frame.reset() takes every allocation back at once, and the spool ends with its scope.

^T@s is a pointer into the spool s, and fn tree() -> ^Node@sp given sp: Spool is a function that builds in whichever spool the caller gives (tree(4, given: frame)), or the heap if the call gives none. A parameter written ^Node takes a tree from any spool. A warp that holds pointers (Node) is Node@s for the spool its nodes are in.

samples/own_spools.loomruns
use std.io.print
use std.mem.{Arena, Spool, kib}

warp Node {
    case Leaf(i32)
    case Pair(^Node, ^Node)
}

// The tree lives in whichever spool the caller gives; with none it is on the heap.
fn tree(depth: i32) -> ^Node@sp given sp: Spool {
    if depth == 0 { return ^Node.Leaf(1) }
    ^Node.Pair(tree(depth - 1), tree(depth - 1))
}

// A parameter without a region takes a tree from any spool.
fn count(n: ^Node) -> i32 = match n {
    .Leaf(k) => k
    .Pair(a, b) => count(a) + count(b)
}

fn main() {
    spool frame = Arena(1.kib())
    let t = tree(4, given: frame)
    print("{count(t)}")
    frame.reset()                       // every node goes at once
    let u = tree(3, given: frame)
    print("{count(u)}")
    print("{count(tree(5))}")           // no spool: the heap
}
Output
16
8
32

The region checker keeps pointers from outliving their spool: a value that points into a spool can't be returned out of the block the spool ends with (R0101), used after the spool was reset (R0102), or passed where a parameter names another spool (R0104). A spool can't be moved (M0107).

Text copied with .copy() goes in the spool the call is given, so an arena's tree can hold names and still go at once. A list, map or box can't be held by a warp that is in a spool yet (U0102): nothing would free it.

Pool[T](n) is a spool of n slots of one type: put takes a free slot and free gives it back, a few instructions each. It holds plain data only. SharedArena(cap) is an arena threads may allocate in, and its pointers may cross to them; a pointer into any other spool can't (R0103).

given

A function can say what it needs from its caller with a given parameter of a weft: fn welcome(who: str) given g: Greeter. It is passed on by the call, not in the argument list: the innermost given in scope supplies it, given name = value states one from there to the end of the block, and given: x gives one to a single call. A weft marked #given_default(Type) has one when nothing is in scope (a spool's is the heap), so a program that never says given still runs. A function is checked for the type it is given, so an unused given costs nothing. Every function spells its own givens: a private one doesn't infer them from what it calls yet.

samples/own_given.loomruns
use std.io.print

// A weft with a default: a call that is given nothing gets a `Plain`.
#given_default(Plain)
weft Greeter {
    fn greet(self) -> String
}

warp Plain: Greeter, Default {
    pub fn greet(self) -> String = "hello"
}

warp Loud: Greeter {
    name: String

    pub fn greet(self) -> String = "HELLO, {.name}!"
}

fn welcome(who: str) -> String given g: Greeter = "{g.greet()} {who}"

fn main() {
    print(welcome("ann"))          // nothing given: a Plain
    given g = Loud("ci")           // from here to the end of the block
    print(welcome("dee"))
    print(welcome("eve", given: Plain()))    // this one call
}
Output
hello ann
HELLO, ci! dee
hello eve
