Chapter 7

Moves, once and defer

Who owns a value, what a parameter can do with it, and what runs when a scope ends.

Values first#

Every variable owns its value. There is no type "reference to T", so there are no lifetimes to write. Assigning a value or passing it to a take parameter copies it if its type is Copy and moves it otherwise. A warp whose fields are all Copy is Copy by itself, unless it's a once warp.

A function's parameters say what it may do:

DeclaredCall siteThe callee
x: Tf(x)reads x; the caller keeps it
mut x: Tf(mut x)edits x in place; the caller keeps it, changed
take x: Tf(x)owns x; the caller loses it unless T is Copy

mut is written at the call site as well as the declaration. Method receivers are the exception: scores.sort() is already clear.

own_params.loomruns
use std.io.print

warp Counter: Show {
    n: i32 = 0
}

// `x: T` reads. `mut x: T` edits in place. `take x: T` consumes.
fun peek(c: Counter) -> i32 = c.n
fun bump(mut c: Counter) { c.n += 1 }
fun swap(mut a: i32, mut b: i32) {
    let t = a
    a = b
    b = t
}
fun keep(take names: List[String]) -> usize = names.len()

fun main() {
    var c = Counter()
    bump(mut c)                              // `mut` is written at the call, too
    bump(mut c)
    print("{peek(c)} {c}")

    var a = 1
    var b = 2
    swap(mut a, mut b)
    print("{a} {b}")

    // Mutable exclusivity works per field.
    var pair = (10, 20)
    swap(mut pair.0, mut pair.1)
    print(pair)

    // Assigning a `Copy` value copies it.
    var d = c
    d.n = 100
    print("{c.n} {d.n}")

    let names: List[String] = ["ada", "alan"]
    print(keep(names))
}
Output
2 Counter(n: 2)
2 1
(20, 10)
2 100
2

Moves are checked#

Using a variable after it moved is an error, and so is moving a value out of a borrow (a read parameter, a loop's item, a lambda's captured variable) or out of a list's element. The check follows branches and goes through loop bodies twice.

own_err_moved.loomdoesn't compile: M0101
fun keep(take s: String) -> String = s

fun used_after(take s: String) -> usize {
    let kept = keep(s)
    s.len()
}

fun main() {}
The compiler says
error[M0101]: `s` is used after it was moved
  --> own_err_moved.loom:5:5
  |
4 |     let kept = keep(s)
  |                     - moved here
5 |     s.len()
  |     ^ used here
  |

While a variable is lent as mut, nothing else in the call may touch it. The check works per field, so swap(mut p.x, mut p.y) is fine.

fun swap(mut a: i32, mut b: i32) {
    let t = a
    a = b
    b = t
}

fun main() {
    var n = 1
    swap(mut n, mut n)
}

A borrow lasts as long as the call that received it, so a function can't return one or store one. A local can hold a value that borrows another local (a slice of a list, a stream over one, a lambda), and it sees that local as it is now. When the local changes, a borrow made earlier can't be used:

own_err_borrow.loomdoesn't compile: M0105
use std.io.print

fun main() {
    var xs: List[i32] = [1, 2, 3]
    let tail = xs[1..]
    xs.push(4)
    print(tail)
}
The compiler says
error[M0105]: `tail` borrows `xs`, which changed after it was made
  --> own_err_borrow.loom:7:11
  |
6 |     xs.push(4)
  |     -- `xs` changes here
7 |     print(tail)
  |           ^^^^ used here
  |
  = note: `tail` reads `xs` as it is now, not as it was
  = help: make `tail` after the change, or from a copy (`xs.copy()`)

error: own_err_borrow.loom failed to type-check (1 error)

Nor can a borrow outlive what it borrows. A lambda that uses variables around it is passed as an argument or kept in a local, and that's all: returning it, storing it in a warp or a list, or passing it to a take parameter is an error, and so is keeping it in a variable declared outside the block of a variable it uses. The same goes for a slice of a local list, and a stream made from one or from such a lambda. (A lambda that uses nothing around it is a plain function value, and goes anywhere.)

The codes are M0101 (use after move), M0102 (move out of a borrow), M0103 (move out of an element), M0104 (overlapping mut), M0105 (a stale borrow) and M0106 (a borrow that outlives what it borrows).

once warps#

A once warp describes values that must be used up exactly once. They can't be copied, and they can't just go out of scope. The ways to use one up are to destructure it (let Tx(moves) = self, which only code that can see its fields may do) or to pass it to a take parameter that does. A warp that holds a once value is once itself, and so is List[Tx].

own_once.loomruns
use std.io.print

// A `once` value must be used up exactly once. Here that means calling
// `commit` or `rollback`, which take it and unpack it.
pub once warp Tx {
    moves: List[i32] = List()

    pub fun begin() -> Tx = Tx()
    pub fun credit(mut self, amount: i32) { .moves.push(amount) }
    pub fun commit(take self) {
        let Tx(moves) = self                 // destructuring ties the value off
        print("committed {moves}")
    }
    pub fun rollback(take self) {
        let Tx(_) = self
        print("rolled back")
    }
}

fun transfer(good: bool) {
    var tx = Tx.begin()
    defer tx => tx.rollback()                // runs only if `tx` is still loose
    tx.credit(5)
    if not good { return }                   // leaving early rolls back
    tx.commit()                              // used up: the defer does nothing
}

fun main() {
    transfer(true)
    transfer(false)
}
Output
committed [5]
rolled back

The compiler tracks each path. A once value that might still be loose when its scope ends, or when a return, fail, ? or break leaves, is a loose end:

own_err_loose.loomdoesn't compile: L0301
pub once warp Tx {
    moves: List[i32] = List()

    pub fun begin() -> Tx = Tx()
    pub fun commit(take self) {
        let Tx(moves) = self
    }
    pub fun rollback(take self) {
        let Tx(_) = self
    }
}

fun forgetful(early: bool) {
    let tx = Tx.begin()
    if early { tx.commit() }
}

fun main() {}
The compiler says
error[L0301]: loose end: `tx` is never tied off
   --> own_err_loose.loom:14:9
   |
14 |     let tx = Tx.begin()
   |         ^^ `Tx` is a `once` type: it must be used up exactly once
15 |     if early { tx.commit() }
16 | }
   | - ...but it is still loose when the scope ends here
   |

   = help: or add `defer tx => tx.commit()` right after it's created

Nothing of this exists at run time: once is checked entirely at compile time.

defer#

defer runs code when its scope ends, however it ends: normally, or through return, fail, ?, break, continue or an unravel. Defers run in reverse order of declaration. A return value is worked out before the defers run. A defer can't change control flow: return, fail, ?, break and continue in one are T0118.

own_defer.loomruns
use std.io.print

fun plain() {
    defer print("declared first, runs last")
    defer print("declared second, runs first")
    print("body")
}

// The result is worked out before the defers run.
fun returns(n: i32) -> i32 {
    var x = n
    defer print("defer sees x = {x}")
    if n > 5 { return x * 10 }
    x += 1
    x
}

warp Oops: Error {
    case Bad
}

// A defer runs on every way out: `return`, `fail`, `?`, `break`,
// `continue`, and an unravel.
fun fails(bad: bool) -> i32 ! Oops {
    defer print("cleanup after fails({bad})")
    if bad { fail .Bad }
    1
}

fun main() {
    plain()
    print(returns(3))
    print(returns(9))
    print("{fails(false):?}")
    print("{fails(true):?}")

    for i in 0..4 {
        defer print("end of iteration {i}")
        if i == 1 { continue }
        if i == 2 { break }
        print("iteration {i}")
    }
}
Output
body
declared second, runs first
declared first, runs last
defer sees x = 4
4
defer sees x = 9
90
cleanup after fails(false)
ok(1)
cleanup after fails(true)
err(Bad)
iteration 0
end of iteration 0
end of iteration 1
end of iteration 2

A fallback defer, defer tx => tx.rollback(), names a once value and runs only on exits where that value is still live. It's how the transfer function above rolls back on an early exit without doing it after a commit. Giving tx a new value re-arms it.
