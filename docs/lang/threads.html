Language / Threads

Threads

Loom blocks, threads that can't outlive them, and what they may share.

A loom block is a scope where threads run, and every one of them is done before the block ends. thread e starts e as a thread of the innermost loom around it, and gives a Spun[T] for the T it computes. h.join() waits for it and gives the T.

samples/threads_basic.loomruns
use std.io.print
use std.sync.sched_yield

fn square(n: i32) -> i32 = n * n

fn worker(name: str, steps: i32) {
    for i in 0..steps {
        print("{name} {i}")
        sched_yield()                    // let the others take a turn
    }
}

fn main() {
    // `thread` starts a thread; `join` waits for its result. The block's
    // value is its last expression's.
    let total = loom {
        let a = thread square(3)
        let b = thread square(4)
        a.join() + b.join()
    }
    print("total {total}")

    // A thread runs as soon as it's started, until it finishes or
    // yields. Nobody joined these: the block's end waits for them.
    loom {
        thread worker("a", 2)
        thread worker("b", 2)
        print("started")
        ()                               // not a handle: it can't leave the block
    }
}
Output
total 25
a 0
b 0
started
a 1
b 1

What a thread runs

A thread runs as soon as it's started, until it finishes or parks: waits in a join, or calls sched_yield(), which sends it to the back of the queue. Then another one runs, and the one that started it goes on. Nothing is preempted, so a program's output is the same on every run, and on both backends. (This is the schedule with one worker. Several workers at once come later.)

A thread nobody joined is joined where the block ends. The block's value is its last expression's: a thread there would be a handle, which can't leave the block (C0404), so end the block with (), or join it.

What a thread may share

Threads borrow local variables directly, with no copies and no Arc, because nothing outlives its loom. The checker keeps that safe:

  • What's declared outside the loom is shared. A thread may read it; if it changes it, no other thread may touch it, nor the parent, until it's joined (C0401, C0402).
  • What's declared inside the loom block (a loop variable, a local of the block, the parameter of a lambda around the thread) is copied into the thread when it starts: it may be gone by the time the thread runs. A thread can't change its copy (C0405), and a variable that isn't Copy can't be given to it that way.
  • thread is only allowed inside a loom (C0403), and the loom is the innermost one around it, also from inside a lambda or another thread.
samples/threads_share.loomruns
use std.io.print

fn main() {
    // What's declared outside the loom is shared: a thread reads it, or
    // changes it when no one else touches it until it's joined.
    var count = 0
    let words = ["red", "green", "blue"]
    loom {
        let t = thread { count = words.len() }
        t.join()
    }
    print("count {count}")

    // A thread started in a loop gets a copy of what the loop declares.
    let lens = loom {
        var out: List[usize] = []
        for w in words {
            let t = thread w.len()
            out.push(t.join())
        }
        out
    }
    print("{lens}")
}
Output
count 3
[3, 5, 4]

The race detector is the type checker:

use std.io.print

fn main() {
    var hits = 0
    loom {
        thread { hits += 1 }
        thread { hits += 1 }
        ()
    }
    print(hits)
}

Sharing what changes: Atomic

An Atomic[T] (T an integer of 8 to 64 bits, or bool) is changed through methods that only take self to read, so any number of threads can use one at once, with no C0401. Every operation is a whole step: add gives the value before, compare_exchange says whether it swapped.

samples/threads_atomic.loomruns
use std.io.print
use std.sync.Atomic
use std.sync.sched_yield

fn main() {
    let hits = Atomic[u32](0)
    loom {
        for id in 0..3 {
            thread {
                for _ in 0..2 {
                    let before = hits.add(1)
                    print("thread {id} saw {before}")
                    sched_yield()
                }
            }
        }
        ()
    }
    print("hits {hits.load()}")

    // Only one of two racers gets to set it.
    let winner = Atomic[i32](0)
    let (a, b) = winner.compare_exchange(0, 1)
    let (c, d) = winner.compare_exchange(0, 2)
    print("{a} {b}, {c} {d}")
}
Output
thread 0 saw 0
thread 1 saw 1
thread 2 saw 2
thread 0 saw 3
thread 1 saw 4
thread 2 saw 5
hits 6
true 0, false 1

A thread that spins on load() waiting for another doesn't let it run (nothing is preempted yet): put a sched_yield() in the loop.

When something goes wrong

A thread that unravels fails its loom: the other threads are cancelled, and the parent unravels with the thread's message where it sees it, at the join or where the block ends, after everything has stopped. A cancelled thread unwinds from where it waits (join, sched_yield, a yield or pull), running its defers, and nobody sees the cancel: mend doesn't catch it. The same goes for leaving the block early with ?, return or break, for process.exit in a thread, and for Ctrl-C.

A thread started in a loom that has already failed never runs.

Rules

  • A loom block's own defers run when its block ends, before it waits for its threads.
  • Results nobody joined are dropped where the loom ends.
  • A Spun is joined once; a second join unravels (a once result makes the handle once, so it's L0301 to lose it).
  • yield and pull can't be inside a loom block yet (U0102).
  • Compile-time code can't start threads (K0104).
