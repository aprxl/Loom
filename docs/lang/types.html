Language / Warps, wefts and weaves

Warps, wefts and weaves

Data types, behavior types, and how they are joined.

A warp is a data type. A weft is a set of behavior. A weave gives a warp a weft's behavior. There is no inheritance.

Records

A warp with fields is a record. Fields can have defaults. A method takes self, and a function without self is an associated function, called on the type: Point.origin().

Construction is a call. Point(3, 4) takes the fields in order, and Point(y: 2) names one and leaves the rest at their defaults. There are no Point { x: 1 } literals, so if x == Foo { is never ambiguous.

A named argument with nothing after the colon passes the variable of that name: Point(x:, y:) is Point(x: x, y: y), and connect(host:, port: 8080) mixes the two. It works in patterns too: let Point(x:, y:) = p binds x and y.

samples/types_records.loomruns
use std.io.print

warp Point: Show {                           // `Show` is derived: nothing to write
    x: f64 = 0                               // fields can have defaults
    y: f64 = 0

    fn len(self) -> f64 = (.x * .x + .y * .y).sqrt()   // `.x` is `self.x`
    fn origin() -> Point = Point()           // no `self`: called as `Point.origin()`
    fn shift(mut self, dx: f64) { .x += dx }
    const UNIT = Point(1, 0)
}

warp Meters(f64)                             // a tuple warp with one field

fn main() {
    let p = Point(3, 4)                      // construction is a call
    let q = Point(y: 2)                      // named; x takes its default
    print("{p} {q} {p.len()}")
    print("{Point.origin()} {Point.UNIT}")

    var moving = Point()
    moving.shift(2.5)
    print(moving)

    // A dot-block edits a value and gives it back.
    let moved = p.{ .x += 10 }
    print("{moved} {p}")

    // Any warp can be shown in its debug form with `:?`.
    let m = Meters(5.5)
    print("{m:?} {m.0}")
}
Output
Point(x: 3.0, y: 4.0) Point(x: 0.0, y: 2.0) 5
Point(x: 0.0, y: 0.0) Point(x: 1.0, y: 0.0)
Point(x: 2.5, y: 0.0)
Point(x: 13.0, y: 4.0) Point(x: 3.0, y: 4.0)
Meters(5.5) 5.5
  • The leading dot. .x means "relative to the thing in context". In a method that's self, so .x is self.x and .0 is self.0. In a dot-block it's the block's subject. Where a type is expected, it's one of that type's cases: .Red is Color.Red.
  • Dot-blocks. expr.{ ... } opens a block with expr as its subject. On a fresh value or an immutable place it yields the edited value (p.{ .x += 10 } above). On a var it edits the variable in place and yields ().
  • Show. A warp is shown with {p} only if it weaves Show, which needs no code. Any warp can be shown in its debug form with {p:?}.
  • Tuple warps. warp Meters(f64) is a record with one positional field. It has no body, so its methods go in a weave, where .0 means self.0.
  • Visibility. Fields and items are private to their module unless marked pub. pub(get) makes a field readable everywhere and writable only inside its module.

Cases

A warp with case lines is a sum type. Fields written beside the cases belong to every case, and can be read without a match.

samples/types_cases.loomruns
use std.io.print

warp Shape: Show {
    case Circle(radius: f64)
    case Rect(w: f64, h: f64)
    case Dot                                 // no payload

    fn area(self) -> f64 = match self {
        .Circle(r) => 3.14159 * r * r
        .Rect(w, h) => w * h
        .Dot => 0
    }
}

// Fields written beside the cases belong to every case.
warp Token: Show {
    line: u32

    case Word(String)
    case Number(i64)
    case End
}

fn main() {
    let shapes = [Shape.Circle(2.0), .Rect(w: 3, h: 4), .Dot]
    for s in shapes {
        print("{s}: {s.area()}")
    }

    let t = Token.Number(42, line: 7)
    print("{t.line}: {t}")          // `line` needs no `match`
    if t is .Number(n) and n > 40 {
        print("big number {n}")
    }

    // `match` must cover every case.
    let name = match t {
        .Word(w) => w
        .Number(_) => "a number"
        .End => "the end"
    }
    print(name)
}
Output
Circle(radius: 2.0): 12.56636
Rect(w: 3.0, h: 4.0): 12
Dot: 0
7: Number(42)
big number 42
a number

Wefts and weaves

A weft lists methods. A method with a body is a default. A warp joins a weft inline by listing it in its header, or separately with weave, which can live in another module.

samples/types_wefts.loomruns
use std.io.print

weft Shape {
    fn area(self) -> f64
    fn name(self) -> str = "shape"           // a default method
}

// Inline: the warp lists the weft and writes its methods.
warp Circle: Shape {
    radius: f64
    fn area(self) -> f64 = 3.0 * .radius * .radius
}

warp Rect {
    w: f64
    h: f64
}

// Separate: behavior added afterwards, possibly in another module.
weave Shape into Rect {
    fn area(self) -> f64 = .w * .h
    fn name(self) -> str = "rect"
}

fn describe(s: Shape) -> String = "{s.name()} with area {s.area()}"

fn main() {
    print(describe(Circle(2)))
    print(describe(Rect(2, 3)))
    print(Shape.name(Rect(1, 1)))            // call through the weft
}
Output
shape with area 12
rect with area 6
rect
  • A weft can require other wefts (weft Ord: Eq) and can have associated types (type Item; see Iter in std.iter).
  • Shape.name(x) calls a weft's method explicitly. A default method is checked for each type that uses it.
  • weave W into T is allowed only when W or T is defined in your program (T0115 otherwise).
  • A weft used as a parameter type is a generic: see Generics and any.

Deriving

List Show, Eq, Ord or Hash in a warp's header and leave the methods out, and the compiler supplies them:

  • Show writes the debug form, less any fields every case shares: Point(x: 3, y: 4).
  • Eq: every field is equal and, for a warp with cases, it's the same case.
  • Ord: fields compare in order and the first difference decides. Earlier cases come first.
  • Hash makes a warp a usable map key. Error gets a message that is its Show form.

A derived method needs every field to weave the weft too.

samples/types_derive.loomruns
use std.io.print

// List `Show`, `Eq`, `Ord` or `Hash` and leave the methods out:
// they work field by field.
warp Version: Show, Eq, Ord, Hash {
    major: u32
    minor: u32
}

warp Level: Show, Eq, Ord {
    case Low
    case Mid(u8)
    case High
}

fn main() {
    let a = Version(1, 4)
    let b = Version(1, 10)
    print("{a} {a == b} {a < b}")

    // For a warp with cases, earlier cases come first.
    print("{Level.Low < Level.High} {Level.Mid(3) < Level.Mid(5)} {Level.Mid(9) < Level.High}")

    var versions = [b, a, Version(0, 9)]
    versions.sort()
    print(versions)

    // `Hash` makes a warp usable as a map key.
    var notes: Map[Version, str] = Map()
    notes[a] = "old"
    notes[Version(1, 4)] = "still the same key"
    print("{notes.len()} {notes[a]}")
}
Output
Version(major: 1, minor: 4) false true
true true true
[Version(major: 0, minor: 9), Version(major: 1, minor: 4), Version(major: 1, minor: 10)]
1 still the same key

Right now these defaults are built into the compiler. They're meant to become ordinary default methods that inspect the type with reflection, as ToJson does.

through

through forwards a field's methods, so a warp can reuse another's behavior without inheriting from it. Fields aren't forwarded, a method the outer warp defines wins, and a Button is not a Frame.

samples/types_through.loomruns
use std.io.print

warp Frame {
    w: u16
    h: u16
    fn size(self) -> (u16, u16) = (.w, .h)
    fn describe(self) -> String = "frame {.w}x{.h}"
}

// `through` forwards the field's methods. There is no inheritance:
// a Button is not a Frame.
warp Button {
    through frame: Frame
    label: String

    fn describe(self) -> String = "button '{.label}' over {.frame.describe()}"   // overrides
}

fn main() {
    let b = Button(Frame(10, 3), "OK")
    print(b.size())                          // forwarded from Frame
    print(b.describe())                      // Button's own
    print(b.frame.w)                         // fields aren't forwarded
}
Output
(10, 3)
button 'OK' over frame 10x3
10

Method lookup

x.f(args) looks for, in order:

  1. a method in x's warp body;
  2. a method from a weave into x's type;
  3. for something with items that isn't a stream (an array, list, slice, range, or a type that weaves Iter), a method of Stream;
  4. a method forwarded through through;
  5. a free function in scope whose first parameter accepts x.

Two matches at one level are an ambiguity error; write Weft.f(x) or module.f(x) to choose.

samples/types_ufcs.loomruns
use std.io.print

// Any free function is a method on its first parameter.
fn kib(n: usize) -> usize = n * 1024
fn shout(s: str) -> String = s.to_upper()

fn main() {
    print(64.kib())                          // the same as kib(64)
    print("hi".shout())
}
Output
65536
HI
