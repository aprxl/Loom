Language / Gauges

Gauges

Number types limited to a range or a predicate.

A gauge is a numeric type with a restriction: a range (u16 where 1..) or a predicate written as a hole lambda (i64 where _ % 2 == 0).

A gauge is its own type. It widens to its base type by itself (a Port is a u16), and has its base's methods. Getting a number into a gauge is checked:

FormWhen the value is outside
a literal or a constantcompile error (G0201)
x as Portunravels
x as? Portgives an optional
x as| Portclamps into the range (range gauges only)
if x is Port { ... }the test fails; inside the branch x is a Port

Arithmetic on range gauges follows intervals at compile time. Cents + Cents can't go below zero, so it's still Cents. Cents - Cents can, so it's a plain i64. Overflow still unravels as usual.

samples/gauges_basic.loomruns
use std.io.print

// A gauge is a number type limited to a range or a predicate.
type Cents = i64 where 0..
type Port = u16 where 1..
type Percent = f32 where 0.0..=1.0
type Even = i64 where _ % 2 == 0

fn fee(balance: Cents, amount: Cents) -> Cents =
    if balance >= 1000_00 { 0 } else { (amount / 100).max(25) }

fn parse_cents(s: str) -> ?Cents {
    let n = s.parse[i64]() mend return none
    if n is Cents { n } else { none }        // `is` narrows `n` inside the branch
}

fn main() {
    let a: Cents = 250                       // a literal is checked while compiling
    let b: Cents = 100
    let sum = a + b                          // Cents + Cents can't go below zero: still Cents
    let diff = a - b                         // could go below zero: a plain i64
    let wide: i64 = a                        // a gauge widens to its base type
    print("{sum} {diff} {wide} {fee(50_00, 1234_00)}")

    // Getting a checked value into a gauge from somewhere else:
    print("{parse_cents("42"):?} {parse_cents("-3"):?}")
    print("{(-5) as? Cents:?} {7 as? Cents:?}")     // `as?` gives an optional
    print("{70000 as| Port} {1.7 as| Percent}")     // `as|` clamps into the range
    print("{12 as Even}")                            // `as` unravels when it doesn't fit
}
Output
350 150 250 1234
some(42) none
none some(7)
65535 1
12

A gauge's bounds must be known at compile time: literals and constants, not the result of a function call (T0103). A literal outside the range is an error at the literal:

samples/gauges_err.loomdoesn't compile: G0201
type Cents = i64 where 0..

const REFUND: Cents = -1

fn main() {}
The compiler says
error[G0201]: `-1` is outside the gauge `Cents`
  --> gauges_err.loom:3:24
  |
3 | const REFUND: Cents = -1
  |                        ^ `Cents` is 0..
