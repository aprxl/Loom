Language / Not supported yet

Not supported yet

What the compiler doesn't do, said plainly.

The design in README.md and design/*.md is bigger than what runs. This is the list of what doesn't run, from design/lua-backend.md and from trying it.

Anything not built stops with a U code, and most stop with U0102, "not implemented yet". The compiler doesn't guess and doesn't miscompile.

Next in line

These are planned next, in this order: the rest of threads, then spools and the rest of Loom's own VM, Treadle (designed in design/vm.md). Treadle already runs everything: loom run --backend vm file.loom. A program over one of its limits (a frame of more than 65 535 registers, say) stops with U0103.

Threads

Threads run, one at a time: loom { }, thread, .join() and sched_yield(). Not yet: several worker threads at once, loom(given: pool), and yield or pull inside a loom block (U0102).

samples/nyet_threads.loomdoesn't compile: U0102
fn main() {
    // A loom on a pool of its own: not yet. (A loom runs its threads one
    // at a time.)
    let pool = 4
    loom(given: pool) {
        ()
    }
}
The compiler says
error[U0102]: not implemented yet: `loom(given: …)`
  --> nyet_threads.loom:5:10
  |
5 |     loom(given: pool) {
  |          ^^^^^^^^^^^ not supported by this compiler yet
  |
  = note: the type checker grows one milestone at a time; see design/lua-backend.md

error: nyet_threads.loom failed to type-check (1 error)

Spools

spool bindings, Arena, region pointers (^T@s), and the region checker that goes with them. Pointers into the heap (^e, ^T) run: see Moves. std.mem declares Arena and Spool.

samples/nyet_spools.loomdoesn't compile: U0102
use std.mem.Arena

warp Particle {
    x: f32
}

fn main() {
    spool frame = Arena(1024)
}
The compiler says

Compile-time code

The standard library's std.sys is not built, and neither are T.bits (which needs #layout(bits)), f.ty or T.weaves(W):

samples/nyet_sys.loomdoesn't compile: U0102
fn main() {
    let size = std.sys.page_size()
}
The compiler says
error[U0102]: not implemented yet: `std.sys`, the platform's own APIs
  --> nyet_sys.loom:2:20
  |
2 |     let size = std.sys.page_size()
  |                    ^^^ not supported by this compiler yet

error: nyet_sys.loom failed to resolve (1 error)

Array lengths and gauge bounds must be something the compiler's own evaluator can fold. A call to one of your functions isn't. It's U0102 for an array length and T0103 for a gauge bound.

samples/nyet_types.loomdoesn't compile: U0102
// A type can't depend on the compile-time sandbox yet, only on what the
// constant folder can work out: literals, constants, arithmetic.
fn square(n: usize) -> usize = n * n

const AREA: usize = square(4)

fn main() {
    let cells = [0u8; AREA]
}
The compiler says
error[U0102]: not implemented yet: array lengths that aren't known at compile time
  --> nyet_types.loom:8:23
  |
8 |     let cells = [0u8; AREA]
  |                       ^^^^ not supported by this compiler yet

Also missing:

  • const fns that return types (const fn fixed(...) -> type), and anonymous warp { ... } types (U0101).
  • break and continue out of a const for.
  • const parameters that aren't integers or bool.
  • embed and embed_text, and the bolt.loom manifest.

Memory and safety

  • given parameters, ref warp, a for loop over a projection that lends many places, and xs[i] through an Index weave.
  • unsafe blocks, raw pointers (*T), extern "C", Volatile. #layout(...) is parsed but nothing acts on it.
  • User-written Spool weaves.
  • The region checker. Lambdas, slices and streams can't outlive the locals they borrow (M0106), but nothing checks region pointers yet.

Types and library

  • Integers wider than 64 bits and f16.
  • Generic wefts (weft From[T]).
  • xs.sorted_by(...) on a list or an array (it takes a stream: xs.take(n).sorted_by(...), or map.pairs().sorted_by(...)), and other list methods the design mentions that std doesn't declare. std.list and std.slice list what exists.
  • Reading standard input. std.io has print and nothing else.
  • A mut self method of a scalar type can't be called through any yet, because the any holds its own copy.
  • A union of errors doesn't convert to any Error.
  • A warp that writes its own eq and hash is still keyed structurally in a Map or Set.

Running programs

  • Ctrl-C handling (exit status 130), process.exit, an instruction budget for loom run, and running a bundle in an outside Lua (--lua PATH).
  • Async I/O and composing shuttles (lexer().feed(parser())) aren't in the design for this version.
  • The emitted Lua isn't optimized: checks the compiler could prove unneeded are still emitted. Speed comes later, with Loom's own interpreter.

The examples

examples/tour.loom, examples/widgets.loom, examples/ledger.loom, examples/lexer.loom and examples/chip8.loom compile and run. examples/compile_time.loom fails only at std.sys. examples/calc.loom needs spools, given and ref warp, and examples/parallel.loom needs threads.
