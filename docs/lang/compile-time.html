Chapter 11

Compile-time code

Constants computed by ordinary code, const expressions, const assert, and the sandbox they run in.

Loom has no macro language. Code that runs while the program compiles is ordinary Loom. The keyword const marks where: a constant's initializer, an expression, an assertion, a parameter, a condition, a loop. This page covers the first three and the limits. Const parameters and control flow covers the rest.

const fun means "compile-time only" in Loom, as in Zig's comptime. It is not Rust's const fun, which means "may also run at compile time". You don't mark functions: the compiler checks each function when a compile-time expression calls it.

Constants#

A constant's initializer runs while the program compiles. It can use loops, locals and any function, so a lookup table is just code.

ct_table.loomruns
use std.io.print

// A constant's initializer is ordinary code. It runs while the program
// compiles, so the table is ready before `main` starts.
const SQUARES: [u32; 8] = {
    var table = [0u32; 8]
    for i in 0u32..8 {
        table[i] = i * i
    }
    table
}

fun fib(n: u64) -> u64 = if n < 2 { n } else { fib(n - 1) + fib(n - 2) }

// Any function can run at compile time. There's nothing to mark.
const FIB_20 = fib(20)

const assert(SQUARES[7] == 49, "seven squared")
const assert(FIB_20 == 6765)

fun main() {
    print(SQUARES)
    print(FIB_20)
}
Output
[0, 1, 4, 9, 16, 25, 36, 49]
6765
  • A constant is named in SCREAMING_CASE with two or more characters.
  • Constants are lazy. Each is computed the first time something needs it, so the order they're written in doesn't matter.
  • const LIMIT = 15 with no type works like a literal: each use gets the type its context needs. const LIMIT: u32 = 15 has one type everywhere.
  • The result can't depend on anything outside the program. Compile-time code is deterministic: the same source always gives the same value.

const expressions#

const expr runs expr while compiling, once, and every use reads the result. const { ... } is the block form, and its locals stay inside it. A const expression can go anywhere an expression can, including default arguments and field defaults. In a function body it's a constant of its own, so const fib(20) in a loop is computed once.

ct_expr.loomruns
use std.io.print

fun fib(n: u64) -> u64 = if n < 2 { n } else { fib(n - 1) + fib(n - 2) }

fun nth_fib(i: usize) -> u64 {
    // A `const` block is worked out once, while compiling. Every call
    // of `nth_fib` reads the same table.
    let table = const {
        var t = [0u64; 20]
        for k in 0..20 {
            t[k] = fib(k as u64)
        }
        t
    }
    table[i]
}

fun main() {
    // `const` in front of an expression: the call runs while compiling.
    print(const fib(25))
    print(nth_fib(10))
    print(nth_fib(19))
}
Output
75025
55
4181

Constants are values#

A constant is one value, and every use of it gets a value of its own. var mine = PRIMES copies the list, Copy or not, so changing mine leaves PRIMES alone. Reads that don't own, such as PRIMES.len() or for x in PRIMES, share it.

ct_copies.loomruns
use std.io.print

const PRIMES: List[u32] = [2, 3, 5, 7]

fun main() {
    // Every use of a constant gets a value of its own.
    var mine = PRIMES
    mine.push(11)
    print("{mine} {PRIMES}")
}
Output
[2, 3, 5, 7, 11] [2, 3, 5, 7]

const assert#

const assert(condition, message) is checked while compiling. It can go at the top of a module, in a warp body, or in a function body. A failed one is K0101, and it stops the build. In generic code it's checked once for each instance, and the error names the instance (see Const parameters).

The condition can call any function, as crc32(...) in examples/compile_time.loom does. The message can hold {...} holes.

ct_err_assert.loomdoesn't compile: K0101
const LIMIT = 10

fun double(n: i32) -> i32 = n * 2

const assert(double(LIMIT) == 20, "doubling works")
const assert(double(LIMIT) == 21, "this one is wrong")

fun main() {}
The compiler says
error[K0101]: const assertion failed: this one is wrong
  --> ct_err_assert.loom:6:14
  |
6 | const assert(double(LIMIT) == 21, "this one is wrong")
  |              ^^^^^^^^^^^^^^^^^^^ this is false

error: ct_err_assert.loom failed to compile (1 error)

A plain assert(...) inside compile-time code is a different thing. It unravels like any other code, and the unravel is a compile error (K0103, below). Use const assert when you mean to check something while compiling.

The sandbox and its limits#

Compile-time code runs in a sandbox: on Treadle, Loom's own VM, inside the compiler, whichever backend the program is for. Every limit is a compile error with a K code.

Budget: K0102#

All compile-time code shares one budget: 100 million steps (loop iterations and calls), 1 GiB of memory, and 20 seconds. A loop that never ends stops with K0102 instead of hanging the compiler.

ct_err_budget.loomdoesn't compile: K0102
// Compile-time code runs under a step budget, so a loop that never
// ends can't hang the compiler.
const FOREVER: u32 = {
    var n = 0u32
    while n < 10 {
        n = (n +% 1) % 5
    }
    n
}

fun main() {}
The compiler says
error[K0102]: compile-time code ran out of steps
  --> ct_err_budget.loom:3:7
  |
3 | const FOREVER: u32 = {
  |       ^^^^^^^ while computing `FOREVER`
  |
  = note: stopped at ct_err_budget.loom:5:5
  = note: compile-time code may take 100000000 steps in all; this may never stop

error: ct_err_budget.loom failed to compile (1 error)

Unravelling: K0103#

If compile-time code unravels (overflow, a bad index, unravel, a failed as), the constant it was computing fails with K0103, and the message says where it unravelled. Things that needed that constant are skipped, so one failure isn't reported many times.

ct_err_unravel.loomdoesn't compile: K0103
// Unravelling while compiling is a compile error.
const HUGE: u8 = {
    var x: u8 = 250
    for _ in 0..10 {
        x += 1
    }
    x
}

fun main() {}
The compiler says
error[K0103]: compile-time code unravelled: arithmetic overflow
  --> ct_err_unravel.loom:2:7
  |
2 | const HUGE: u8 = {
  |       ^^^^ while computing `HUGE`
  |
  = note: it unravelled at ct_err_unravel.loom:5:9
  = help: unravelling while compiling is a compile error

error: ct_err_unravel.loom failed to compile (1 error)

No I/O: K0104#

The sandbox has no way out. Everything in std.io, std.env, std.fs, std.time and std.term fails with K0104, and the note says which call, and where it was called from.

ct_err_io.loomdoesn't compile: K0104
use std.io.print

fun loud(n: i32) -> i32 {
    print("computing")
    n
}

// Printing is I/O. The compile-time sandbox has none.
const NOISY: i32 = loud(3)

fun main() {}
The compiler says
error[K0104]: `std.io.print` can't run at compile time
  --> ct_err_io.loom:9:7
  |
9 | const NOISY: i32 = loud(3)
  |       ^^^^^ while computing `NOISY`
  |
  = note: called at ct_err_io.loom:4:5
  = note: compile-time code computes; it can't read or write anything outside the compiler

error: ct_err_io.loom failed to compile (1 error)

No locals from outside: K0105#

Compile-time code runs before the program does, so a local variable of the surrounding function has no value yet. Constants, functions and the code's own locals are fine.

ct_err_local.loomdoesn't compile: K0105
fun twice(n: i32) -> i32 = n * 2

fun f(n: i32) -> i32 {
    let a = const twice(4)
    let b = const twice(n)
    a + b
}

fun main() {}
The compiler says
error[K0105]: `n` has no value while compiling
  --> ct_err_local.loom:5:25
  |
3 | fun f(n: i32) -> i32 {
  |       - declared outside it, so it gets its value when the program runs
4 |     let a = const twice(4)
5 |     let b = const twice(n)
  |                         ^ read by compile-time code
  |
  = help: compile-time code can use constants, functions and its own locals

error: ct_err_local.loom failed to type-check (1 error)

No leaving: K0106#

return, break, continue, ?, yield and pull can't leave compile-time code, exactly as in a defer. Handle the case inside: with mend, or an if.

ct_err_flow.loomdoesn't compile: K0106
fun f() -> i32 {
    let x = const {
        return 0
    }
    x
}

fun main() {}
The compiler says
error[K0106]: `return` can't leave compile-time code
  --> ct_err_flow.loom:3:9
  |  
2 |       let x = const {
  | /-------------'
3 | |         return 0
  | |         ^^^^^^^^ this would leave the `const` code
4 | |     }
  | \-----' it runs while compiling, from here
  |  
  = note: compile-time code runs before the program does, so it can't change where the program goes
  = help: handle it inside: `mend`, or an `if`

error: ct_err_flow.loom failed to type-check (1 error)

No cycles: K0107#

A constant that needs its own value, through any number of other constants and functions, is K0107.

ct_err_cycle.loomdoesn't compile: K0107
const ALPHA: i32 = BETA + 1
const BETA: i32 = helper()

fun helper() -> i32 = ALPHA * 2

fun main() {}
The compiler says
error[K0107]: `ALPHA` needs its own value
  --> ct_err_cycle.loom:1:7
  |
1 | const ALPHA: i32 = BETA + 1
  |       ^^^^^ computing this reads it again
  |
  = note: read again at ct_err_cycle.loom:4:5

error: ct_err_cycle.loom failed to compile (1 error)

A constant can't change: K0108#

A constant is one value that every use copies, so it can't hold something that changes as it's used: a shuttle, a stream or a once value.

ct_err_holds.loomdoesn't compile: K0108
fun numbers(n: i32) ~> i32 {
    for i in 0..n {
        yield i
    }
}

// A constant is a value that every use copies. A shuttle can't be one.
const NUMBERS: Shuttle[i32, ()] = numbers(3)

fun main() {}
The compiler says
error[K0108]: a constant can't hold a shuttle
  --> ct_err_holds.loom:8:7
  |
8 | const NUMBERS: Shuttle[i32, ()] = numbers(3)
  |       ^^^^^^^ this is `Shuttle[i32, ()]`
  |
  = note: every use of a constant gets the same value, and a shuttle changes as it's used
  = help: make it in a function, and call that where it's needed

error: ct_err_holds.loom failed to type-check (1 error)

The constant folder#

Two things are decided by a small evaluator in the compiler itself, not by the sandbox: what a const argument, a const if condition or a const for sequence is, and array lengths and gauge bounds. It handles literals, constants, const parameters, arithmetic, comparisons, and/or/not, an array's .len(), a few integer methods, and reflection. A top-level const assert that it can decide is reported without running the sandbox. When it can't work something out, you get K0109 or K0110 (see the next page), or U0102 for an array length or a type.

How it runs#

The compiler builds the "jobs": the constants, const expressions and const asserts. Only what they reach is built, as a program for Treadle, which it runs in its own process. Then it builds the real program with what the jobs computed written into it: a constant that is a number, text, a tuple, an array, a list, a record or an optional of those (not too big) is data in the program, or a literal in the Lua bundle, and nothing computes it when the program runs. A constant of another type (a map, a sum) is computed when it's first read, as it would be anyway.

loom build, run, test and check all run the compile-time jobs.

Not supported yet#

Types computed by const funs are not built (reflection is). embed and embed_text don't exist, and neither does bolt.loom. See Not supported yet.
