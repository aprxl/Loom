Language / Optionals and errors

Optionals and errors

?T, T ! E, and the ? and mend pair.

Loom has two kinds of "didn't work": absence (?T) and failure (T ! E). One operator leaves either, and one keyword recovers from either.

Syntax
optional?T, with values some(x) and none
resultT ! E, with values ok(v) and err(e); fn f() ! E when there's no success value
raisefail e
bail outpostfix ?
recoverexpr mend fallback, expr mend e => handler
give upunravel("message")

Optionals

A T converts to ?T by itself, so a function that returns ?i32 can end with a plain number. ? unwraps an optional. If there's no value, it jumps to the nearest mend around it, or leaves the function with none if there isn't one. That one rule covers early return, optional chaining and try/catch.

samples/errors_optional.loomruns
use std.io.print

fn find(xs: [i32], target: i32) -> ?usize {
    for (i, x) in xs.indexed() {
        if x == target { return some(i) }
    }
    none
}

fn first_even_plus_one(xs: [i32]) -> ?i32 {
    let e = xs.find(_ % 2 == 0)?             // no value: leave the function with `none`
    e + 1                                    // a plain value converts to `?i32`
}

fn main() {
    let xs = [3, 5, 8, 9]
    print("{find(xs, 8):?} {find(xs, 4):?}")
    print("{first_even_plus_one(xs):?} {first_even_plus_one([1, 3]):?}")

    // `mend` gives a fallback.
    let i = find(xs, 4) mend 0
    print(i)

    // `?` jumps to the nearest `mend`, so a block can be a `try`.
    let n = {
        let a = "12".parse[i32]()?
        let b = "x".parse[i32]()?
        a + b
    } mend e => {
        print("could not add: {e:?}")
        -1
    }
    print(n)

    // `is` binds, and `and` sees the binding.
    if find(xs, 9) is some(k) and k > 2 {
        print("found late at {k}")
    }
}
Output
some(2) none
some(9) none
0
could not add: Invalid
-1
found late at 3
  • mend has the lowest precedence of any binary operator, so put parentheses around it in arithmetic: (counts.get(k) mend 0) + 1.
  • A ? has to sit inside the left side of the mend it jumps to. It can cross loops and blocks, but not a lambda or a shuttle.
  • mend chains left to right: a() mend b() mend 8080.
  • In mend e => ..., e is the union of everything that can reach the mend.

Results and error types

An error is a warp that weaves Error, usually with cases. Error gives it a message that shows the case and its payload. fail .Empty leaves the function with an error, and the leading dot picks the case from the declared error type.

A ? that leaves a function converts the error. A from case absorbs another error type: case Parse(from ParseError) means a ? on a ParseError wraps it as .Parse(...). At most one case can absorb a given type.

samples/errors_results.loomruns
use std.io.print

warp ParseError: Error {
    case Empty
    case NotANumber(text: String)
}

warp RangeError: Error {
    case TooBig(limit: u8)
}

warp AppError: Error {
    case Parse(from ParseError)              // `?` on a ParseError wraps it here
    case Range(from RangeError)
}

fn parse(text: str) -> u32 ! ParseError {
    if text.is_empty() { fail .Empty }
    text.parse[u32]() mend fail .NotANumber(text: text.to_string())
}

fn small(n: u32) -> u8 ! RangeError {
    n as? u8 mend fail .TooBig(limit: 255)
}

fn load(text: str) -> u8 ! AppError {
    let n = parse(text)?                     // ParseError becomes AppError.Parse
    small(n)?
}

fn main() {
    for text in ["42", "", "abc", "1000"] {
        match load(text) {
            ok(v) => print("ok {v}")
            err(e) => print("error: {e}")
        }
    }
}
Output
ok 42
error: Parse(Empty)
error: Parse(NotANumber(text: "abc"))
error: Range(TooBig(limit: 255))

Several error types

A | B is a union type, mostly used for errors. Each member converts to the union, and a match takes the members apart with type patterns. any Error accepts an error of any one type, which is handy for main and scripts.

samples/errors_union.loomruns
use std.io.print

warp IoProblem: Error {
    case Unreadable(path: String)
}

warp BadText: Error {
    case Garbled
}

fn read(path: str) -> str ! IoProblem {
    if path == "missing" { fail .Unreadable(path: path.to_string()) }
    path
}

fn decode(text: str) -> i32 ! BadText {
    if text == "junk" { fail .Garbled }
    42
}

// A union type: the error is one or the other. Each error widens to it.
fn load(path: str) -> i32 ! (IoProblem | BadText) {
    let text = read(path)?
    decode(text)?
}

// `any Error` accepts an error of any type.
fn run(path: str) ! any Error {
    let text = read(path)?
    let v = decode(text)?
    print("loaded {v}")
}

fn main() {
    for path in ["config", "missing", "junk"] {
        match load(path) {
            ok(v) => print("ok {v}")
            err(e: IoProblem) => print("io: {e.message()}")
            err(e: BadText) => print("text: {e.message()}")
        }
    }
    run("config") mend e => print("run failed: {e}")
    run("junk") mend e => print("run failed: {e}")
}
Output
ok 42
io: Unreadable(path: "missing")
text: Garbled
loaded 42
run failed: Garbled
A union of errors doesn't convert to any Error yet: ? on a ! (A | B) inside a ! any Error function is T0108. Widen the function's errors to the union instead.

main

fn main() ! E lets ? leave main. An error that reaches the end is printed as error: ... on stderr, and the program exits with status 1.

samples/errors_main.loomexits with an error
use std.io.print

warp ConfigError: Error {
    case Missing(key: String)
}

fn setting(key: str) -> u16 ! ConfigError = fail .Missing(key: key.to_string())

// An error that reaches the end of `main` is shown, and the program
// exits with status 1.
fn main() ! ConfigError {
    print("starting")
    let port = setting("port")?
    print("never printed: {port}")
}
Output
starting
Error output
error: Missing(key: "port")

unravel

unravel(message) is for bugs, not for expected failures. Its type is never. It unwinds the current thread and runs defers on the way out. Plain arithmetic overflow, a failed as, an out-of-range index and a failed assert all unravel. The program exits with status 101.

samples/errors_unravel.loomunravels
use std.io.print

fn inner() {
    defer print("inner cleanup")
    unravel("something that should never happen")
}

// `unravel` is for bugs. It unwinds, running each `defer` on the way out.
fn main() {
    defer print("outer cleanup")
    inner()
    print("never printed")
}
Output
inner cleanup
outer cleanup
Error output
unravel: something that should never happen
  --> errors_unravel.loom:5:5
  |
5 |     unravel("something that should never happen")
  |     ^

assert(condition, message) unravels unless the condition holds. In compile-time code a failed assertion is a compile error: see Compile-time code.
