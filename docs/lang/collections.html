Chapter 5

Collections and streams

Arrays, lists, slices, maps, sets, and lazy streams.

Arrays, lists and slices#

  • [T; N] is a fixed-size array. [1, 2, 3] is one, and [0u8; 4] repeats a value.
  • List[T] is a growable array. A literal becomes a list where a list is expected: let xs: List[i32] = [1, 2].
  • [T] is a slice, a view of contiguous Ts. An array or a list passes as a slice, and has every slice method.

Indexing is bounds-checked, and an out-of-range index unravels. get gives an optional instead. xs[a..b] makes a view without copying. A view reads the list as it is now, so changing the list while a view is live is an error (M0105). for mut x in xs edits the elements in place.

coll_lists.loomruns
use std.io.print

fun total(xs: [i32]) -> i32 {                 // `[i32]` is a slice: arrays and lists pass as one
    var t = 0
    for x in xs { t += x }
    t
}

fun main() {
    let fixed = [1, 2, 3]                    // an array: `[i32; 3]`
    let zeros = [0u8; 4]                     // repeat: four zero bytes
    var xs: List[i32] = [5, 3, 8]            // a literal where a list is expected
    xs.push(1)
    xs.insert(0, 9)
    print("{xs} len {xs.len()} first {xs.first():?} last {xs.last():?}")

    xs.sort()
    print(xs)
    print("{total(fixed)} {total(xs)} {total(xs[1..3])}")   // slicing makes a view
    print("{zeros} {xs.contains(8)} {xs.index_of(8):?}")

    // Indexing is bounds-checked; `get` gives an optional instead.
    print("{xs[0]} {xs.get(99):?}")

    // `for mut` edits the elements in place.
    for mut x in xs { x *= 2 }
    print(xs)

    print(xs.map(_ + 1))
    print(xs.chunks(2).collect())
}
Output
[9, 5, 3, 8, 1] len 5 first some(9) last some(1)
[1, 3, 5, 8, 9]
6 26 8
[0, 0, 0, 0] true some(3)
1 none
[2, 6, 10, 16, 18]
[3, 7, 11, 17, 19]
[[2, 6], [10, 16], [18]]

An index whose type can't reach past the end (a u4 into a [u8; 16]) needs no check.

The methods are listed in std.list and std.slice. On slices and lists, map and filter are eager and make new lists. The stream methods are lazy.

Inside x[...], # is the length of x: xs[#-1] is the last element, xs[1..#-1] leaves out the first and last, and xs[#-3..] is the last three. On text it's the length in bytes. x has to be a name or a field (self.items[#-1]), so it's never evaluated twice; for anything else, bind it with let first. xs[#-1] on an empty list unravels, because #-1 overflows.

A list comprehension builds a list from a loop: [for n in 1..=10 if n % 2 == 0 => n * n] is [4, 16, 36, 64, 100]. The if is optional, the pattern is a for pattern, and the result is always a List. It is the loop that pushes each element, so ?, moves and borrows inside it work as they would in that loop.

Maps and sets#

Map[K, V] and Set[T] remember the order things were first added, and going through one, or showing it, follows that order. Keys must weave Hash, which a warp gets by listing it. m[k] unravels when the key is missing, and m.get(k) gives an optional. m[k] = v adds or replaces. [:] is the empty map literal.

coll_maps.loomruns
use std.io.print

fun main() {
    // Maps and sets remember insertion order.
    var ages: Map[str, u8] = ["ada": 36, "alan": 41]
    ages["grace"] = 85                       // adds a key
    ages["ada"] = 37                         // replaces a value
    print("{ages} {ages.len()}")
    print("{ages["alan"]} {ages.get("nobody"):?} {ages.has("ada")}")

    for (name, age) in ages {
        print("{name} is {age}")
    }
    print(ages.keys().collect())
    print(ages.remove("alan"))
    print(ages.sorted())

    // Counting words.
    var counts: Map[String, u32] = Map()
    for word in "the cat and the hat and the bat".words() {
        counts[word.to_string()] = (counts.get(word.to_string()) mend 0) + 1
    }
    print(counts)

    var seen: Set[i32] = Set()
    for n in [3, 1, 3, 2, 1] {
        if seen.insert(n) { print("new: {n}") }
    }
    print("{seen} {seen.sorted()} {seen.has(2)}")
}
Output

Two maps are equal when they hold the same pairs in any order. See std.map and std.set.

Streams#

A Stream[T] is a lazy sequence: nothing runs until something asks for the next item. Every stream method takes the stream, so a stream is read once: using it again after s.map(f) or s.count() is a move error (M0101). chars(), bytes(), lines(), words(), indexed(), chunks(n) and windows(n) make streams. Ranges, arrays, lists, slices and maps have every stream method, and so does any type that weaves Iter. for loops over any of them.

To make your own, weave Iter: give the type an Item and a next that returns ?Item.

coll_streams.loomruns
use std.io.print

// Anything `for` can loop over is an `Iter`. Give a type `next` and it
// gets every `Stream` method for free.
warp Countdown: Iter {
    n: u32
    type Item = u32
    fun next(mut self) -> ?u32 {
        if .n == 0 { return none }
        .n -= 1
        .n + 1
    }
}

fun main() {
    // Streams are lazy: nothing runs until something asks for an item.
    let evens = (1..=20).filter(_ % 2 == 0).map(n => n * n)
    print(evens.take(4).collect())

    print("hello world".chars().filter(_ != 'o').count())
    print("one two  three".words().join("-"))
    print(Countdown(4).collect())
    print(Countdown(5).sum())

    for (i, line) in "a\nb\nc".lines().indexed() {
        print("{i}: {line}")
    }

    let xs = [4, 8, 15, 16, 23, 42]
    print("{xs.fold(0, (acc, x) => acc + x)} {xs.max():?} {xs.position(_ == 15):?}")
    print("{xs.all(_ > 3)} {xs.exists(_ > 40)} {xs.zip(xs.skip(1)).count()}")
    print(xs.windows(2).map(w => w[1] - w[0]).collect())
}
Output
[4, 16, 36, 64]
9
one-two-three
[4, 3, 2, 1]
15
0: a
1: b
2: c
108 some(42) some(2)
true true 5
[4, 7, 1, 7, 19]

sum and product need Num, min and max need Ord, and join needs Show. See std.iter for the whole list. A generator function makes a stream too: see Shuttles.
