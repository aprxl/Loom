std / iter

std.iter

Iteration: the Iter weft (what for loops over), Stream (a lazy sequence and its many methods), Range (a..b), and Shuttle (generators and coroutines). Lists, arrays, slices, maps, sets and ranges all have the methods of Stream, and nothing is computed until something asks for the next item.

source: runtime/std/iter.loomread about it in the book →
iter_example.looman example to run
use std.io.print

fun main() {
    // Nothing runs until `collect` asks for items.
    let squares = (1..=10).filter(_ % 2 == 0).map(n => n * n)
    print(squares.collect())
    let words = ["warp", "weft", "weave", "loom"]
    print(words.indexed().map(p => "{p.0}:{p.1}").join(" "))
    print(words.map(_.len()).sum())
}

warp Range[T] builtin #

The type of a..b, a..=b and a..: the values from a up to b. It has the methods of Stream (over its values), and these.

fun chunks(self, n: usize) -> Stream[Range[T]] #

Ranges of n values at a time, one after another: (0..10).chunks(4) is 0..4, 4..8 and 8..10. Each one is a range too, with all the methods of one, so it can be given to a thread. Unravels if n is 0 or the range has no end.

fun rev(self) -> Stream[T] #

The values from the last to the first. Needs room for all of them, and unravels for a range with no end.

warp Stream[T] builtin #

A lazy stream of Ts: s.chars(), xs.indexed() and stream.map(f) are streams. Nothing is computed until something asks for the next item.

Everything else with items has these methods too: arrays, lists and slices, ranges, and types that weave Iter. (1..=10).filter(_ % 2 == 0) is a stream of the range's items.

The methods that make a new stream use up this one: a stream is read once.

warp Shuttle[T, U] builtin #

A shuttle: a function paused between the Ts it yields and the Us it pulls. Calling fun f() ~> T <~ U makes one without running any of it.

A generator (~> T, which pulls nothing) is a stream of what it yields: for x in fib(), fib().take(10).

fun push(mut self, take input: U) -> Burst[T] #

Resumes it with input as the value of its pending pull (the first push starts it), once what's left of the last burst has run. The burst is what it yields before its next pull.

fun close(mut self) -> Burst[T] #

Makes its pending and later pulls give none, once what's left of the last burst has run. The burst is what it yields from here on.

once warp Burst[T] builtin #

What a shuttle yields between one input and its next pull. It's lazy: going through it is what runs the shuttle. It's once, so outputs can't be dropped by accident: go through it with for (or a Stream method), or drain() it.

fun drain(take self) #

Runs the shuttle to its next pull, throwing away what it yields.
